# 维护指南

公开与本地资料的边界见[公开范围说明](PUBLIC_PRIVATE.md)。内容源为 `data/cases.json`。中英双语入口 README、`browse/` 分类页、`cases/` 详情、`prompts/` 和 `docs/COVERAGE.md` 统计由脚本生成，编辑内容源后再生成，避免手工改动丢失。

## 新增或更正案例

1. 按[发现与筛选流程](DISCOVERY.md)查重并核对作者原帖及模型说明；提示词可以来自同一作者的回复，不能把转载者或 AI 推测当作原文。
2. 记录中英双语标题、独立简介、用途和必要素材；有公开原始指令用 `original`，只有转述用 `brief`，未取得指令用 `unknown` 且留空正文。来源已核对但资料待完善的记录标 `stage=discovery`，整理完成后标 `stage=catalogued`；精选单独选择。未开展可选视听评价时可保留 `verification.fullReview=false`，不得据编目或起播填成 `true`。
3. 封面保存到 `assets/covers/<原帖 ID>.jpg`，不超过 250 KB，记录媒体来源和取帧时间。
4. 互动数字来自同一个原帖和采集时间；未知值保留 `null`。不要混用回复的点赞与主帖的浏览量。
5. 运行下面的检查，通过 PR 提交数据和生成文件。

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/build.mjs --check
node scripts/check-release.mjs
```

Node.js 22+，无需安装依赖。CI 在推送、PR 和手动触发时执行同样的检查，不联网刷新指标，不使用 API Key。

## 播放来源

`webPlayback` 只记录从对应作者 X 原帖核对取得的 `video.twimg.com` 视频。有可播放来源时，GitHub 首页、分类卡片及详情的封面与主观看链接统一打开在线画廊的对应作品播放器（`#case-作品ID`，英文保留 `?lang=en`），作者 X 原帖和 GitHub 文字详情作为独立入口保留。无可播放来源时，明确标成「在 X 原帖观看」并回退原帖。GitHub Markdown 页本身仍是封面入口，不标成页内播放器。不要把裸 MP4 当成导航入口，浏览器可能拦截，来源头也可能被媒体服务拒绝。不再使用参考仓库的 GitHub 附件作为视频来源，旧 `playback` 字段会被数据校验拒绝。

有作者公开交互网页时，可添加 `demoUrl`；它与 `codeUrl`、作者原帖分开显示，不用视频录屏替代交互入口。不要把交互演示或作者任务转述标成完整提示词。

核验须对应原帖 ID、作者与视频媒体；可记录时长并检查画廊入口。完整视听评价另行记录，不影响收录。参考仓库只用于找原帖，不把其附件当成作者原媒体。不得保存带 JWT 的短期签名地址。

用户要求本地下载时，从已核对原帖返回的媒体 URL 保存至被 Git 忽略的 `.research/`，同时记录原帖、媒体 URL、文件 hash、大小、时长和可选视听评价状态。下载成功不代表完成视听评价或可重新发布。公开视频仍为外部引用；当前 `reuploadPermission` 为 `not_verified`，视频文件不提交到 Git 历史。

外部媒体失效时先复查原帖，失败则移除 `webPlayback` 并保留原帖入口。权利人请求移除时同时检查 README、案例页、提示词、封面和数据记录。

播放器缺少后续数据时启动缓冲超时判断，计时到期再次检查播放状态；已有播放数据时不把网络停滞误报为播放失败。真正载入失败仍保留重试与作者原帖入口。

## 指标刷新

在 `metrics` 中记录同一原帖的收藏、点赞、浏览量及核对时间，`sourceUrl` 必须是该作品的作者原帖。未知数字保留 `null`；未取得新快照时保留原数字和时间。更新后运行 `node scripts/build.mjs`。采集工具和原始响应不在公开仓库分发。指标更新不代表重新确认作品质量。

## 发布

正式发布仓库是 `guanmo-ai/awesome-ai-motion`，由 `scripts/build.mjs` 的 `REPOSITORY` 常量与 `data/cases.json` 的 `repository` 字段共同校验。发布前执行：

```sh
node scripts/check-target.mjs
```

提交前使用公开署名和 GitHub noreply 邮箱。`check-release.mjs` 在本地检查下一次提交的作者与提交者身份，在 CI 检查当前提交，要求公开署名与 GitHub noreply 邮箱（CI 允许贡献者署名）；同时检查工作树与暂存版本，拒绝私有配置、密钥、符号链接和混入公开数据的研究字段。该检查不能清除历史提交中的身份，历史清理须另行审查并保留本地恢复备份。

该检查核对 `origin` 的推送地址，阻止发布到其他账户或仓库。个人 fork 可用于贡献，只有正式发布需要此检查。合入 `main` 前确认 CI 通过。发布说明只写已验证的实际能力；修改排序或媒体方式时同步更新来源说明。原创脚本的 MIT 不覆盖第三方媒体与提示词。

正式仓库 `main` 的推送会自动触发网站发布，部署前仍执行完整检查。获准推送后，应继续跟进对应提交的部署结果与线上页面，确认网站同步更新后再完成交付；流程见[运行与发布画廊](DEPLOYMENT.md)。

## 作品画廊

`index.html` 与 `assets/gallery.*` 提供静态画廊，直接读取同一份 `data/cases.json`。本机运行 `PORT=4178 node scripts/serve.mjs`，打开 `http://127.0.0.1:4178`；仅绑定本机地址，静态文件仅开放画廊所需资产，不开放研究目录；另有仅限本机页面使用的精选、删除与恢复接口。

README 保持短目录，分类页显示作品封面，长提示词和来源留在详情。根地址直接显示完整作品目录，旧 `?page=home` 和 `?page=all` 链接归一到该目录；首批显示 36 条，可选择每次再显示 108 条或一次显示当前筛选结果中的全部作品；剩余不足 108 条时显示实际剩余数。展开全部仍保留图片延迟加载和视频进入视口才载入，筛选或排序改变时恢复首批。用途、搜索与资料条件可以组合，URL 保留浏览条件和作品 ID。首次打开默认按原帖收藏快照降序展示，显式选择「推荐浏览」可切换回精选排序；分享链接省略默认收藏排序参数，显式精选链接保留 `sort=featured`。

详情中的上一条、下一条和左右方向键按当前筛选及排序切换，包含分类中尚未加载到的作品；首页打开的详情按全库收藏顺序切换。首尾不循环。连续切换不会叠加详情历史，关闭后保留原列表、已加载批次和浏览位置。输入与视频控件、全屏视频及画中画保留原生方向键行为。

桌面详情沿用线上横屏作品的窗口尺寸规则，以固定 16:9 为宽度计算基准；同一视口下所有作品的弹窗和外层播放区域尺寸一致，不随视频比例、元数据加载或提示词展开改变。视频在区域内按实际比例完整居中，播放控件贴合画面，周围以低亮度的模糊画面色彩衬托；标题、作者和资料位于下方。环境背景不增加另一份视频播放，暂停、切换作品或离开页面时停止更新；减少动态效果或省流量模式使用静态封面背景。手机采用单列布局和统一的横向播放框，弹窗保留接近全屏的空间；低高度窗口通过弹窗内部滚动访问其他操作。支持原生全屏的浏览器提供「全屏观看」入口，放大或退出不重新载入视频；Escape 先退出全屏，再次按下关闭详情。不支持全屏时隐藏该入口，全屏请求被拒绝不会被当作视频加载失败。

新增案例后，除数据校验外，应在浏览器确认分类能找到作品、封面可见、视频实际起播或有明确原帖入口。不存在或已移除作品的分享链接会显示提示，关闭或继续浏览保留原有筛选。检查旧链接时也要覆盖中英文、Escape 关闭和返回浏览。

上线时只发布画廊公开文件，不公开 `.research/`、Git 元数据或本机缓存。启用公开托管与本地完成是两个独立步骤；未实际上线前不要在 README 宣称已有在线地址。

### 源码、演示与工具

可选 `resources` 数组记录资源入口：`kind=code` 为该作品工程或完整可读 HTML，`demo` 为在线作品，`tool` 为作者使用或分享的通用工具、Skill 或被介绍的产品仓库。每项填写 `url`、双语 `label` / `labelEn`、链接出处 `evidenceUrl` 和 `checkedAt`；代码与工具还须填写 `license`，未发现许可证时写 `not_specified`。必要说明使用双语 `note` / `noteEn`。许可只描述核对时的原项目，不能覆盖音乐、字体、模型等单独授权的素材。

作者主页上的无关仓库不能直接当作该作品源码。优先核对作者原帖、回复、作品页及仓库内容之间的对应关系。旧 `codeUrl` / `demoUrl` 继续兼容，与新列表重复的地址只展示一次。

已核得许可时，用可选 `licenseUrl` 链接到所核对提交中的许可证原文。保留依赖及素材的单独声明；没有整体许可证时使用 `not_specified`，不能因为仓库公开或可下载就称其允许复用。

生成器同步生成双语资源索引。画廊「有提示词」「有源码」「可体验」按钮可以叠加，再次点击只取消对应条件；源码与体验同时选中时使用 `?resource=both`，要求作品同时具有两种资源。「有提示词」只匹配作者公开原始指令；仅有任务转述不进入该集合。卡片分别提供查看提示词、作者指令、查看源码或在线体验入口。详细页保留出处、许可状态及核对时间。

旧 `?resource=any` 链接包含直接源码或公开作品网页，排除仅有通用工具链接的作品；`code`、`demo` 与 `tool` 链接继续兼容，额外条件会显示为可取消的资料按钮。公开网页不表示已核得完整工程或开源许可。旧链接中的 `duration`、`playable` 和 `prompt=brief/unknown` 条件会移除；README 的源码及提示词原文入口保留。

### 独立画廊播放字段

`webPlayback` 为唯一公开播放来源字段：`kind=external_source_video`、稳定 HTTPS MP4 `url`、`sourcePostUrl`、`checkedAt`、`contentType`、`verificationLevel=source_media_matched`、`reuploadPermission=not_verified`。URL 限定为已从对应原帖取得的 `video.twimg.com` 媒体；公开仅记录原帖媒体已对应的状态，具体读取地址和请求记录保留在本地研究目录。不要从封面字段盲目推断可播放，不接入临时签名 URL。

画廊保留 `<meta name="referrer" content="no-referrer">`：原媒体服务对外站 Referer 返回 403，匿名无 Referer 请求正常。更改此项后必须实际验证独立页面起播，不能只检查 API。

### 本地删除与恢复

当前画廊已移除管理界面。需要删除、恢复或修改评价时，使用 `scripts/curation.mjs` 的本地事务模块；先调用 `snapshot()` 取得当前 `revision`，再调用 `mutate(action, id, revision, review)`。删除使用作品 ID，恢复使用备份的 `key`；不要直接删除恢复记录。该模块同步内容源、双语生成页及封面，并校验修改结果；删除最后一个分类作品时也会清理空分类页。

备份保存在 Git 忽略的 `.research/deleted-works/`，不进入公开静态目录。操作失败会尝试回滚；服务重启时恢复尚未完成的事务。保留该目录才能恢复已删除作品。不要同时运行两个指向同一仓库的维护服务。

这只修改当前本地仓库，不执行 Git commit、push 或远端删除。审阅完成且明确授权推送后，GitHub 对应内容才会随删除提交一起更新。静态公开部署没有维护接口，访客看不到删除入口。

接口校验本机 Host、请求来源和会话令牌，并拒绝过期数据版本；若生成页有手工改动，会停止覆盖并指出文件。先核对这些修改，再运行生成脚本、刷新后重试。

### 评价与排序

「推荐浏览」先展示精选，再展示认可作品和未评价作品，最后展示「一般，排后」作品。精选与评价通过内容源或上述本地事务模块修改；数据规则要求排后与精选、优点互斥。评价不改变最新发布和收藏排序。

精选和评价保存为案例的可选 `review` 字段：`featured` 为布尔值，明确覆盖内置精选名单；`highlights` 为 `motion` / `overall` 数组，`later` 为布尔值。未设置 `featured` 时沿用内置名单；全空且未设置 `featured` 时删除此字段。修改使用同一本地事务接口及版本保护，不中断正在播放的视频。同步双语分类页顺序和详情评价，README 精选区域只收录当前精选作品，排后作品除外。删除后恢复仍保留精选和评价。所有更改只在本地，须获明确授权后再推送 GitHub。


### 首页导览与创作建议

README 由 `scripts/build.mjs` 生成。首屏用综合排序前 160 个作品组成一张 SVG 封面拼图，按 16 列 × 10 行排成横向长方形；所有封面统一为 16:9 画框、相同宽度，居中裁切，保持原图比例、不拉伸。单张图避免窄屏上文字行高造成封面行间白缝，点击整张拼图进入画廊。下方三列网格使用六张独立的 16:9 缩略图，展示前六个作品，保留标题、作者、收藏快照、发布日期，以及「观看 · 原帖」两项直达操作。提示词、源码等资料继续保留在作品详情和画廊中。分类使用用途说明和计数组织成紧凑目录；收藏榜、策展人标记、来源说明及本机运行方式可展开，分类页仍保留双列预览。

`assets/readme-covers/mosaic.svg` 内嵌 160 张原封面；同目录的六张 `<作品 ID>.svg` 用于推荐卡片，均由生成器构建，无需新增图像处理依赖。原始封面不改动；构建时只清理该目录中已不再使用的数字命名派生图与拼图，本地删除和恢复事务也同步这些文件。发布检查仅为这张合并拼图提供 12 MiB 大小预算，其他文件沿用各自上限；README 派生图不进入静态画廊发布包。

拼接墙与热门卡片共用 `spotlightCases`：综合分等价于 `(收藏数 + 1) × 2^(-发布时间距目录最新作品的天数 / 14)`，发布时间每相差 14 天，较早作品约需两倍收藏数才具有相同权重。计算使用对数避免极旧作品数值下溢，同分按收藏、发布时间和 ID 排序；未知收藏排在已知值之后。不依赖构建当天时间，相同数据会得到相同结果。排序不改变作品的编目、精选或评价状态；删除、取消精选、排后及 `README_EXCLUDED_IDS` 指定的作品不进入拼接墙与热门卡片，其余作品自动补位。仅改变 README 导览，画廊的「收藏最多」「最新发布」仍保持各自原有含义。

画廊默认按全库收藏快照排序，不设作者、类别或精选配额；未知收藏值排在 0 之后，人工设置「一般，排后」不影响收藏排序。展示次序不自动改变精选、编目或可选视听评价状态；详细来源、快照采集时间和核验信息仍可在作品详情中展开。详情的同类相关推荐继续按人工评价与编目状态排序。

案例可带可选的 `guide`：双语 `takeawayZh` / `takeawayEn`、各三条 `stepsZh` / `stepsEn`、原文提到的 `tools` 和可核对的 `evidenceUrls`。建议依据作者公开原文整理，不填补未知制作过程，不声称是作者完整操作记录或已经独立复现；保留原始 `prompt.text` 不变。新增时核对每项建议所据原文。

画廊可见卡片自动静音循环预览，使用同一份已核对的原帖视频；离屏释放视频来源，切换到后台或打开详情时暂停卡片。顶部可暂停或恢复全部预览；资料筛选的组名与结果计数仅供读屏播报，页面通过分类按钮和底部分页显示数量；系统开启减少动态效果或省流量时默认不自动预览。封面保留到视频实际起播，预览失败时回到封面，仍可点击打开详情。首批四张封面优先加载，后续图片延迟加载。筛选与排序复用仍在列表中的卡片与播放器；减少动态效果时关闭卡片及菜单的过渡动画。

点卡片或同类作品会尝试直接播放详情视频；分享链接首次载入的详情保持暂停，由访客决定播放。浏览器若阻止起播，仍可使用原生播放按钮。

静态发布与原帖媒体健康检查见 [运行与发布画廊](DEPLOYMENT.md)。打包只包含画廊需要的公开文件，研究与删除恢复记录不会进入发布包。每日媒体检查只验证地址、响应和 MP4 文件头，失败不会自动删除作品；它与互动指标刷新、浏览器播放和可选视听评价分别记录。
