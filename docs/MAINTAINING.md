# 维护指南

内容源为 `data/cases.json`。中英双语入口 README、`browse/` 分类页、`cases/` 详情和 `prompts/` 由脚本生成，编辑内容源后再生成，避免手工改动丢失。

## 新增或更正案例

1. 按[发现与筛选流程](DISCOVERY.md)查重并核对作者原帖及模型说明；提示词可以来自同一作者的回复，不能把转载者或 AI 推测当作原文。
2. 记录中英双语标题、独立简介、用途和必要素材；有公开原始指令用 `original`，只有转述用 `brief`，未取得指令用 `unknown` 且留空正文。已核原帖但尚未完整审看的新增记录标 `stage=discovery` 和 `verification.fullReview=false`，不得自动升级为精选。
3. 封面保存到 `assets/covers/<原帖 ID>.jpg`，不超过 250 KB，记录媒体来源和取帧时间。
4. 互动数字来自同一个原帖和采集时间；未知值保留 `null`。不要混用回复的点赞与主帖的浏览量。
5. 运行下面的检查，通过 PR 提交数据和生成文件。

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/build.mjs --check
node scripts/check-release.mjs
```

Node.js 22+，无需安装依赖。CI 在推送、PR 和手动触发时执行同样的检查，不联网刷新指标，不使用 API Key。

## 播放来源

`webPlayback` 只记录从对应作者 X 原帖核对取得的 `video.twimg.com` 视频。有可播放来源时，GitHub 首页、分类卡片及详情的封面与主观看链接统一打开在线画廊的对应作品播放器（`#case-作品ID`，英文保留 `?lang=en`），作者 X 原帖和 GitHub 文字详情作为独立入口保留。无可播放来源时，明确标成「在 X 原帖观看」并回退原帖。GitHub Markdown 页本身仍是封面入口，不标成页内播放器。不要把裸 MP4 当成导航入口，浏览器可能拦截，来源头也可能被媒体服务拒绝。不再使用参考仓库的 GitHub 附件作为视频来源，旧 `playback` 字段会被数据校验拒绝。

有作者公开交互网页时，可添加 `demoUrl`；它与 `codeUrl`、作者原帖分开显示，不用视频录屏替代交互入口。不要把交互演示或作者任务转述标成完整提示词。

核验须对应原帖 ID、作者、视频媒体与时长，再检查实际画面与声音。参考仓库只用于找原帖，不把其附件当成作者原媒体。不得保存带 JWT 的短期签名地址。

用户要求本地下载时，从已核对原帖返回的媒体 URL 保存至被 Git 忽略的 `.research/`，同时记录原帖、媒体 URL、文件 hash、大小、时长和审看状态。下载成功不代表已完整审片、正式收录或可重新发布。公开视频仍为外部引用；当前 `reuploadPermission` 为 `not_verified`，视频文件不提交到 Git 历史。

外部媒体失效时先复查原帖，失败则移除 `webPlayback` 并保留原帖入口。权利人请求移除时同时检查 README、案例页、提示词、封面和数据记录。

## 指标刷新

记录原帖公开互动快照及核对时间；更新后运行 `node scripts/build.mjs`。

失败条目保留旧数字与旧时间。刷新不代表重新确认作品质量。当前没有自动定时采集。

## 发布

正式发布仓库是 `guanmo-ai/awesome-ai-motion`，由 `scripts/build.mjs` 的 `REPOSITORY` 常量与 `data/cases.json` 的 `repository` 字段共同校验。发布前执行：

```sh
node scripts/check-target.mjs
```

提交前使用公开署名和 GitHub noreply 邮箱。`check-release.mjs` 在本地检查下一次提交的作者与提交者身份，在 CI 检查当前提交，拒绝自动生成的本机地址；同时拒绝私有配置和密钥文件。该检查不能清除历史提交中的身份，历史清理须另行审查并保留本地恢复备份。

该检查核对 `origin` 的推送地址，阻止发布到其他账户或仓库。个人 fork 可用于贡献，只有正式发布需要此检查。合入 `main` 前确认 CI 通过。发布说明只写已验证的实际能力；修改排序或媒体方式时同步更新来源说明。原创脚本的 MIT 不覆盖第三方媒体与提示词。

## 作品画廊

`index.html` 与 `assets/gallery.*` 提供静态画廊，直接读取同一份 `data/cases.json`。本机运行 `PORT=4178 node scripts/serve.mjs`，打开 `http://127.0.0.1:4178`；仅绑定本机地址，静态文件仅开放画廊所需资产，不开放研究目录；另有仅限本机页面使用的精选、删除与恢复接口。

README 保持短目录，分类页显示作品封面，长提示词和来源留在详情。作品是否公开完整提示词只作为资料标记，不影响用途归类。独立画廊在关闭播放详情后保留分类、搜索和浏览位置；URL 可携带筛选条件和作品 ID。首次打开及无筛选首页默认按原帖收藏快照降序展示，显式选择「推荐浏览」可切换回精选排序；分享链接省略默认收藏排序参数，显式精选链接保留 `sort=featured`。精选、已编目、发现池、时长、提示词状态与分类可组合筛选；列表每批加载 36 条，打开和关闭详情保留已加载批次。

新增案例后，除数据校验外，应在浏览器确认分类能找到作品、封面可见、视频实际起播或有明确原帖入口。不存在或已移除作品的分享链接会显示提示，关闭或继续浏览保留原有筛选。检查旧链接时也要覆盖中英文、Escape 关闭和返回浏览。不能用 HTTP 成功或元数据加载替代完整审片。

上线时只发布画廊公开文件，不公开 `.research/`、Git 元数据或本机缓存。启用公开托管与本地完成是两个独立步骤；未实际上线前不要在 README 宣称已有在线地址。

### 独立画廊播放字段

`webPlayback` 为唯一公开播放来源字段：`kind=external_source_video`、稳定 HTTPS MP4 `url`、`sourcePostUrl`、`checkedAt`、`contentType`、`verificationLevel`、`reuploadPermission=not_verified`。URL 限定为已从对应原帖取得的 `video.twimg.com` 媒体；具体采集细节仅保存在本地研究目录。不要从封面字段盲目推断可播放，不接入临时签名 URL。

画廊保留 `<meta name="referrer" content="no-referrer">`：原媒体服务对外站 Referer 返回 403，匿名无 Referer 请求正常。更改此项后必须实际验证独立页面起播，不能只检查 API。

### 本地删除与恢复

先点击页头「管理作品」，作品卡片和详情才显示「删除」入口，点击后须再点「确认删除」。它会从 `data/cases.json` 移除条目，同步中英 README 与分类页，删除对应双语详情、提示词和不再使用的封面。管理模式下页头「已删除」可恢复，刷新页面或重启服务后记录仍保留。删除最后一个分类作品时，也会清理空分类的生成页。

备份保存在 Git 忽略的 `.research/deleted-works/`，不进入公开静态目录。操作失败会尝试回滚；服务重启时恢复尚未完成的事务。保留该目录才能恢复已删除作品。不要同时运行两个指向同一仓库的维护服务。

这只修改当前本地仓库，不执行 Git commit、push 或远端删除。审阅完成且明确授权推送后，GitHub 对应内容才会随删除提交一起更新。静态公开部署没有维护接口，访客看不到删除入口。

接口校验本机 Host、请求来源和会话令牌，并拒绝过期数据版本；若生成页有手工改动，会停止覆盖并指出文件。先核对这些修改，再运行生成脚本、刷新后重试。

### 评价与排序

在「管理作品」模式中，作品卡片和详情有「精选」按钮，点后保存并调整「推荐浏览」的次序，已精选时可点「取消精选」。详情「评价与排序」支持「动效很酷」「整体优秀」双项标记；「推荐浏览」先展示精选，再展示认可作品和未评价作品，最后展示「一般，排后」作品。两项优点可同时选中；选择「一般，排后」会清除优点和精选，选择精选会取消排后。「清除评价」只清除优点和排后，不改变独立的精选选择。评价不改变最新发布和收藏排序；标为「一般，排后」的作品仍按收藏数进入首页和类别预览。

精选和评价保存为案例的可选 `review` 字段：`featured` 为布尔值，明确覆盖内置精选名单；`highlights` 为 `motion` / `overall` 数组，`later` 为布尔值。未设置 `featured` 时沿用内置名单；全空且未设置 `featured` 时删除此字段。修改使用同一本地事务接口及版本保护，不中断正在播放的视频。同步双语分类页顺序和详情评价，README 精选区域只收录当前精选作品，排后作品除外。删除后恢复仍保留精选和评价。所有更改只在本地，须获明确授权后再推送 GitHub。


### 首页导览与创作建议

无筛选首页先展示全库收藏快照最高的六个作品，再按七个用途分类展示各类收藏最多的预览。这里不设作者、类别或精选配额；未知收藏值排在 0 之后，人工设置「一般，排后」不影响收藏排序。首页展示不自动改变精选、编目或完整审看状态；详细来源、快照采集时间和核验信息仍可在作品详情中展开。详情的同类相关推荐继续按人工评价与编目状态排序。

案例可带可选的 `guide`：双语 `takeawayZh` / `takeawayEn`、各三条 `stepsZh` / `stepsEn`、原文提到的 `tools` 和可核对的 `evidenceUrls`。建议依据作者公开原文整理，不填补未知制作过程，不声称是作者完整操作记录或已经独立复现；保留原始 `prompt.text` 不变。新增时核对每项建议所据原文。

点封面或同类作品会尝试直接播放；分享链接首次载入保持暂停，由访客决定播放。浏览器若阻止起播，仍可使用原生播放按钮。主页首批六张封面优先加载，后续图片延迟加载。

静态发布与原帖媒体健康检查见 [运行与发布画廊](DEPLOYMENT.md)。打包只包含画廊需要的公开文件，研究与删除恢复记录不会进入发布包。每日媒体检查只验证地址、响应和 MP4 文件头，失败不会自动删除作品；它与互动指标刷新、浏览器播放和完整视听审看分别记录。
