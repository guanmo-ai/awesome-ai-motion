# 质量状态与验收标准

本项目把来源核对、媒体可取、浏览器起播、完整审看和编辑推荐分别记录。案例数量说明覆盖范围；只有通过相应检查，才能使用“可播放”“已审看”或“精选”等更强的描述。下文记录 2026-09-27 的对抗审查、已完成的修复验证和仍待完成的条件。

## 本轮复现的观看问题

在公开 GitHub 首页进入 Pocketsflow 作品详情后，封面和主“观看”入口都打开裸 `video.twimg.com` MP4。Chrome 对该直链显示 `ERR_BLOCKED_BY_CLIENT`；同一浏览器打开作者 X 原帖后，视频实际播放到 0:08。测试只确认了这条真实用户路径的结果，未确定浏览器拦截规则的具体来源。

随后对当前 245 条 `webPlayback` 地址逐条请求前 1 KB：不带 Referer 时，245 条均返回 HTTP 206、`video/mp4` 和 MP4 `ftyp` 签名；带 `Referer: https://github.com/` 时，245 条均返回 HTTP 403。Pocketsflow 的 GitHub Referer 结果复试仍是 403。这说明原媒体没有在无 Referer 条件下普遍失效，也说明 GitHub 来源的裸媒体请求不可作为可靠的主观看路径。HTTP 前缀成功不能证明整片可播放。

另以带 `no-referrer` 的测试页面在浏览器中逐条静音起播 245 条视频：每条均推进至少约 0.2 秒，并取得非零尺寸和已解码视频帧。该结果证明当次浏览器环境能够起播这些媒体；没有检查整片、实际声音、卡点或其他浏览器环境。

因此当前成熟度是：**来源和媒体入口已核对，无 Referer 测试页的短时起播已验证；原 GitHub 入口的失败已复现并修复为作者原帖入口，作品视听质量仍需逐条审看。** 公开目录中的“已编目”“发现池”和“精选”应继续区分；前两者不自动意味着完整审看。

主 Agent 复查补充：当前 5 条默认精选没有在案例数据中记录逐条完整视听审看证据。现有标签保留为编辑选择，但尚未满足下表中的完整审看验收条件；不能把默认入选或自动起播测试当作质量验收。

## 验收条件

| 范围 | 可判定完成的证据 |
| --- | --- |
| 来源与编目 | 每条记录能回到作者原帖，作者的创作声明、模型作用、原帖媒体和提示词状态可分别核对；按作品去重，人工删除的作品不因再次发现而恢复。原始指令、作者任务转述与未知信息分别标记。 |
| GitHub 观看路径 | 从公开 README 的封面进入详情后，主“观看”入口和封面在常用浏览器打开对应作者原帖并能起播；原媒体直链如保留，应标成次要入口且有原帖回退。用 Pocketsflow 和各分类代表作品实际点击复查生成页，不能只检查链接字符串。 |
| 分类预览 | 首页每个有足够作品的分类展示 3 张可见、来源正确、点击目标正确的封面，并提供查看全部入口。发现池预览须明确标注待审看，不因占据首页位置而变成精选。窄屏和桌面均检查可读性与入口。 |
| 独立画廊播放器 | 保持无 Referer 的媒体请求；在浏览器验证起播、时间推进和视频帧。模拟媒体超时或错误，确认重试有界、错误可见、作者原帖回退可用，关闭详情后筛选和浏览位置仍可恢复。超时与错误恢复必须分别验证。 |
| 完整视听审看 | 对将标成“已审看”或“精选”的作品，以正常速度看完整片并听实际音轨；检查关键转场、运动、文字、旁白、BGM、音效和声画对应。无音轨要明确记录。缩略图、元数据、Range、自动解码与前 0.2 秒起播均不能代替这一步。 |
| 公开交付 | 生成页与内容源一致，运行受影响测试和 `node scripts/build.mjs --check`；准备发布时再运行仓库的完整测试及发布目标检查。公开页面实际可访问后，才使用已上线的表述。媒体仍归原作者，外链不等于获准重传。 |

## 观看入口修复验证（前一轮）

- 245 条作品的双语 GitHub 详情主观看链接及封面统一指向对应作者 X 原帖，撤除裸 MP4 导航；生成测试逐条覆盖。Pocketsflow 原帖在 Chrome 已实际播放。
- GitHub 首页展示 5 张精选封面与 7 个类别各 3 张预览，共 26 张卡片；分类推荐不会更改作品的精选或完整审看状态。发现池总览有独立入口；全类排后时显示空推荐说明，全部作品仍可访问。
- 本地画廊首页 7 类共 21 张封面。桌面第一屏可见第一类完整封面和下一类别的封面上部；高级筛选默认收起，启用后展开。390 像素布局检查无横向溢出。
- 浏览器实际验证了分类 36 → 45 条加载、搜索、精选筛选、双语切换、关闭详情后的焦点与列表恢复；Pocketsflow 页内播放器时间推进到 7 秒以上。
- 故障测试页分别模拟媒体 404 和持续无响应，均出现可见提示、重试与作者原帖入口。另在本地播放器屏蔽媒体后解除屏蔽，点击重试恢复载入并清除错误。超时为 12 秒，关闭详情会释放请求与计时器。
- 本轮 40 项自动测试、生成一致性、发布内容检查及唯一远程目标检查均通过。

这些结果证明本轮修复的边界，不能证明整库作品都已完整审看或所有环境永久可播。上述修复完成时仍是 GitHub 目录与本地画廊；已编目 36 条与发现池 209 条都不自动等于完整质量验收。

## 产品体验改进与主 Agent 复审

2026-09-27 后续版本把第一次访问的路径收敛为「看封面 → 点击播放 → 看创作线索 → 继续看同类」。首页用六张跨类别、不同作者的封面开场，后续七类各三张预览；共 27 张卡片，部分作品会同时出现在入口和分类中。维护操作默认收起，只有本地点击「管理作品」才出现精选、删除和恢复。

16 个作品补充双语启发与三步尝试建议，覆盖七个用途类别。每项建议核对现有作者公开原文；建议与作者提示词分开显示，不声称已经按其步骤独立复现。新增导览没有修改原文、作者、模型或完整审看状态。

本轮由主 Agent 亲自检查并修正：

- 首屏只按收藏量选作品会出现视觉单调的开场，改为明确的跨风格入口路线；仍尊重人工排后。
- 点击封面后需要再次播放，改为用户点击时直接尝试播放；分享链接载入不自动播放。
- 手机字体过小、品牌换行，已调整；390 像素宽度首页及播放器无横向溢出。
- 播放请求只到达元数据阶段时，不再提前取消等待提示；对持续无响应的测试媒体发送元数据事件后，仍显示超时回退。

浏览器验证包括：原媒体在实际播放器中推进至 27 秒以上；静态项目子路径可载入六张入口封面并播放；静态版本无管理和删除按钮；同类连续观看后按 Escape 返回原卡片，焦点正确；空搜索可清除；分类列表从 36 加载至 45 条并在关闭详情后保留。屏蔽媒体请求会显示重试与原帖入口，解除后重试恢复。复制提示词出现成功反馈；浏览器测试接口使用独立虚拟剪贴板，未通过该接口读取系统剪贴板内容。

当前新增媒体巡检逐条检查 245 个原帖 MP4，245/245 通过。51 项自动测试通过，包含导览结构与安全链接、删除恢复、组合筛选、媒体超时和静态打包排除私有文件。静态包包含 250 个公开文件，约 7.14 MB；不含视频文件、维护 API 或研究资料。

这些结果支持本轮交互与工程改进，仍不能替代全部作品的完整观看和听审。该轮完成时公开 Pages 工作流仅已准备，尚未启用公开网站；后续上线结果见下文。


## 公开上线验收

经所有者授权，GitHub Pages 已以手动 Actions 工作流部署，访问地址为 [Awesome AI Motion 在线画廊](https://guanmo-ai.github.io/awesome-ai-motion/)。[首次部署记录](https://github.com/guanmo-ai/awesome-ai-motion/actions/runs/36377171486)成功，部署版本为 `a55f9d8`，HTTPS 已启用。

主 Agent 在公开网址验证：入口六张封面全部载入；Pocketsflow 播放时间推进到 15.06 秒末尾，取得 1280 像素宽视频画面；搜索与分享直达保持作品和筛选；重新打开分享链接默认暂停；390 像素布局无横向溢出。屏蔽原媒体请求后显示可见错误、重试与作者原帖入口，解除后重试恢复。

在线首页、脚本、样式和案例数据均返回 HTTP 200，内容 hash 与本地已部署版本一致；研究记录、Git 配置和本地维护脚本的请求均返回 404。静态访客不显示管理入口。以上属于上线功能验收，不增加任何作品的完整视听审看或转载许可声明。
