# 发现与核验作品

## 收录范围

新增作品只收录原作者明确宣称使用 Opus 5.5 制作的动效。模型归因以作者原帖或对应回复的自述为依据，不要求独立复现或深查制作证明；其他模型不收，未说明具体模型的暂缓。核心关注代码绘制、渲染或驱动的动效，工具不限，Canvas、SVG、WebGL、Three.js、Remotion、Blender 等均可；3D、叙事形式以及生成图片、音乐等素材的使用不构成排除理由。

探索优先关注图形变化、动态文字、信息可视化、界面动画和程序化三维。代码构建与渲染是技术依据，还须判断具体作品的动效表达与本库是否相关；仅使用 Blender、自动化剪辑或脚本调度不能作为收录理由。画面写实程度不能单独证明制作方式，也不构成整类作品的排除依据。参考照片用于建模不等于以实拍为成片主体；真人及写实人物边界仍按下文执行。

排除以真人为画面主体的作品，包括真人实拍、真人照片或视频、写实数字人或 AI 写实人物，以及真人转为 3D、动画、粒子等混合转换；Opus 编写代码或 Blender 参与也不能豁免。明显卡通、像素与非写实 3D 角色可以收录，人物图标或界面中的缩小头像等非主体装饰不据此排除。已确认含上述真人主体的既有案例须移出，不因制作方式未知而保留。

产品操作录屏、明确由视频模型生成主体画面的作品、Vlog/普通剪辑，以及仅用代码调度视频生成服务而未产生代码动效的作品，不在收录范围内。没有证据表明存在真人主体、但制作方式或代码动效贡献尚不明确的既有案例保留待核。来源和媒体校验、范围判断、完整视听评价分别记录，不能相互替代。

## 核验步骤

候选作品整理自 X（Twitter）原作者公开帖子。正式收录前按以下顺序核对：

1. 确认原帖地址、作者、正文、发布时间和作品媒体；按主帖 ID 与作者自有媒体 ID 去重，同一作品的重编码或再次发布也须核对。尊重已有删除与拒收决定，避免把转载或说明回复当作新作品。
2. 确认原作者在原帖或对应回复中明确宣称使用 Opus 5.5，并简查画面是否符合上述收录范围。把公开指令原文、任务描述和未知信息分别标记；不根据转述补写指令。
3. 核对视频与封面是否对应原帖，确认有可访问的作品入口。新增先检查封面，按风险查看视频中段和末段，不能凭纯动画首帧认定没有真人主体。浏览器起播可用于检查画廊入口，不要求看完整片或听完整音轨；范围核验与完整视听评价分别记录。
4. 记录来源、核对时间和提示词状态。新增作品默认标为 `discovery`；资料整理完成后可标为 `catalogued`，不能因新增或脚本生成自动升级。精选是独立编辑标记。

补充源码时，核对作者给出的仓库、网页或可读 HTML 与具体作品的关系，并检查代码是否完整、是否只有工具模板及许可证范围。在线演示、公开可读源码与有明确开源许可的代码分别描述；搜索结果中的仓库名或同名作者不能独自作为归属证据。公开目录只保存资源链接、必要说明及链接出处，不镜像第三方源码。

无法确认原作者创作、Opus 5.5 自述、直接作品媒体或来源的新增线索暂不进入公开案例；未取得提示词或源码不阻止收录，未知提示词使用 `unknown` 并保留空正文。无真人主体证据的既有制作方式不明案例保留待核；已确认真人主体的案例按上述边界移出。更新不以新增数量为目标；除执行明确移除要求外，不自动改变既有精选、评价及删除决定。

完整视听评价可另行开展；新增作品默认 `verification.fullReview=false`，表示没有已记录的完整视听评价，不影响正常收录。来源核对、部分观看、起播及编目不能把它改为 `true`。权利人提出纠错或移除时，按[第三方内容说明](../THIRD_PARTY.md)和[维护指南](MAINTAINING.md)处理。各状态说明见[质量标准](QUALITY.md)。
