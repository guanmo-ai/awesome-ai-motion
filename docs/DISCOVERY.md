# 发现与核验作品

## 收录范围

核心收录模型编写代码来绘制、渲染或驱动的动效，尤其关注 Opus 5.5 的作品。工具不限，Canvas、SVG、WebGL、Three.js、Remotion、Blender 等均可；3D、叙事形式以及生成图片、音乐等素材的使用不构成排除理由。需要从作者说明、源码或制作过程确认代码实际产生动效；模型名称本身不能证明代码渲染。

明确由视频模型生成主体画面的作品、真人/Vlog/普通剪辑，以及仅用代码调度视频生成服务而未产生代码动效的作品，不在收录范围内。既有案例的制作方式或代码动效贡献尚不明确时，保留待核，不自动删除。来源和媒体校验、范围判断、完整视听评价分别记录，不能相互替代。

## 核验步骤

候选作品整理自 X（Twitter）原作者公开帖子。正式收录前按以下顺序核对：

1. 确认原帖地址、作者、正文、发布时间和作品媒体；按主帖 ID 与作者自有媒体 ID 去重，同一作品的重编码或再次发布也须核对。尊重已有删除与拒收决定，避免把转载或说明回复当作新作品。
2. 核对作者的创作声明、模型或工具在作品中的作用，确认符合上述收录范围，并核对原帖、公开回复和提示词之间的对应关系。把公开指令原文、任务描述和未知信息分别标记；不根据转述补写指令。
3. 核对视频与封面是否对应原帖，确认有可访问的作品入口。浏览器起播可用于检查画廊入口，不要求看完整片或听完整音轨。
4. 记录来源、核对时间和提示词状态。新增作品默认标为 `discovery`；资料整理完成后可标为 `catalogued`，不能因新增或脚本生成自动升级。精选是独立编辑标记。

补充源码时，核对作者给出的仓库、网页或可读 HTML 与具体作品的关系，并检查代码是否完整、是否只有工具模板及许可证范围。在线演示、公开可读源码与有明确开源许可的代码分别描述；搜索结果中的仓库名或同名作者不能独自作为归属证据。公开目录只保存资源链接、必要说明及链接出处，不镜像第三方源码。

无法确认原作者创作、代码动效贡献、直接作品媒体或来源的新增线索暂不进入公开案例；未取得提示词本身不阻止收录，使用 `unknown` 并保留空正文。既有制作方式不明的案例保留待核。更新不以新增数量为目标，也不自动改变既有精选、评价及删除决定。

完整视听评价可另行开展；新增作品默认 `verification.fullReview=false`，表示没有已记录的完整视听评价，不影响正常收录。来源核对、部分观看、起播及编目不能把它改为 `true`。权利人提出纠错或移除时，按[第三方内容说明](../THIRD_PARTY.md)和[维护指南](MAINTAINING.md)处理。各状态说明见[质量标准](QUALITY.md)。
